# 運用・復旧手順

## 監視

- `/api/health/live`: プロセスの死活監視。200以外で再起動します。
- `/api/health/ready`: DB、マイグレーション、seedの準備状況。503が3回続いたらアラートします。
- アプリケーションエラーはJSON形式で標準エラーへ出力し、本番環境のログ収集・通知先へ転送します。通知先と当番連絡先は環境ごとの運用台帳で管理します。

## バックアップと復元

毎日、暗号化されたアクセス制限付き領域へDBとファイルを同時にバックアップします。週1回、隔離環境の空DBへ復元テストを行います。PGliteではアプリを停止してから、PostgreSQLではファイル更新を止めた保守時間帯に取得します。

```sh
pnpm data:backup -- /secure/backups/nursery-YYYYMMDD
RESTORE_CONFIRM=YES pnpm data:restore -- /secure/backups/nursery-YYYYMMDD
```

復元先は空でなければ処理を拒否します。復元後は `pnpm db:check`、対象園の件数、直近資料のダウンロードを確認してから切り替えます。バックアップ暗号鍵はバックアップ本体と別管理にします。

## 保存期間と削除

業務記録は既定7年（2555日）保存します。削除対象は取消済みの連絡帳・お知らせ・予定のみです。通常実行は件数表示だけで、削除は明示指定時に限ります。

```sh
pnpm data:retention
RETENTION_APPLY=YES RETENTION_DAYS=2555 pnpm data:retention
```

法令・自治体・園の契約で異なる期間が必要な場合は、責任者の承認後に環境値を変更します。監査ログと配信実績の削除は、この手順では行いません。

## 障害対応

1. live/ready、直近デプロイ、DB接続数、エラーログを確認する。
2. 書き込みを停止し、障害開始時刻と影響園を記録する。
3. 再送は同じcommand IDを使用し、二重登録を防ぐ。
4. 復旧後、監査ログ・アプリ内通知・ファイル状態を照合する。
5. 原因、影響、再発防止、復旧時刻をインシデント記録に残す。
